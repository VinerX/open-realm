# Warcraft III CASC VFS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Read Warcraft III 3.0 installed CASC resources through OpenRealm's VFS so Lua maps can be tested against the real game data.

**Architecture:** A pinned CascLib adapter opens local `w3` storage and contributes named files to the existing VFS. VFS file handles dispatch read/seek/size/close to MPQ or CASC; map archive handles and map MPQ parsing remain StormLib-owned.

**Tech Stack:** C/C++, GNU Make, StormLib-compatible MPQ VFS, CascLib 3.0 (`4971d36`, MIT), existing in-engine C test runner.

**Spec:** `docs/superpowers/specs/2026-09-26-wc3-casc-vfs-design.md`

## Global Constraints

- Read installed CASC data locally; never contact Blizzard CDNs, download assets, extract the installation, or modify files under the game directory.
- Select CASC product `w3` explicitly.
- Keep MPQ map loading and MPQ-specific operations on StormLib.
- Keep loose-file lookup and existing MPQ precedence unchanged.
- If a recognized CASC root cannot open the requested product, report the path, product, and library error and fail data-directory setup.
- Keep CascLib types and handles out of the public VFS API.
- Ask the user before acquiring or vendoring CascLib.

## Review Focus

- A normal loose/MPQ data directory keeps current behavior — pin in Task 3's `wc3_fs.non_casc_data_directory_unchanged` regression.
- The 3.0 installation selects `w3` and reports a real open/read failure — pin in Task 1's `casc_probe` assertions and output.
- Map MPQ data still overrides base CASC data — pin in Task 3's `wc3_fs.map_priority_mpq_overrides_casc` regression.
- A recognized but unreadable CASC root does not appear successfully mounted — pin in Task 3's setup failure test.
- CASC storage closes after VFS reset and can reopen — pin in Task 3's `wc3_fs.casc_storage_reopens_after_reset` regression.

## File Structure

- `vendor/casclib/**` — pinned upstream CascLib 3.0 sources and MIT license.
- `Makefile` — isolated static CascLib build and `casc_probe` link rule.
- `tools/casc_probe.c` — local-only storage/product/file compatibility diagnostic.
- `common/common.h` — opaque VFS file-operation declarations.
- `common/common.c` — typed mounted sources, lookup order, lifecycle, and VFS read/seek/size/close dispatch.
- `common/fs_casc.c`, `common/fs_casc.h` — CascLib-only storage and file adapter; no CascLib types escape the adapter.
- `games/warcraft-3/tests/test_fs.c` — host-side VFS handle, precedence, failure, and lifetime regressions (the game-test DLL does not link `common/common.c`).
- `games/warcraft-3/game.mk` — include the adapter and CascLib link dependency in WC3 builds/tests.
- `docs/diagnostic-tools.md` — document `casc_probe`.
- `docs/games/warcraft-3/lua-map-runtime.md` — document the tested CASC requirement and map-test invocation.
